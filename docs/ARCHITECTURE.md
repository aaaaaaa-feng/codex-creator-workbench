# 架构说明

```text
浏览器页面 :3000
    ↓ 本机 HTTP / SSE
Codex 桥接 :4317
    ├── Codex SDK → 使用者本机 Codex 线程、MCP 与 Skills
    └── 内容目录 → 00_收件箱 … 04_复盘
```

## 关键边界

- 页面只负责展示、选择和发出指令，不直接保存平台账号或云端凭证。
- 桥接只监听 `127.0.0.1`，并限制浏览器来源为本机工作台。
- Codex 的工作目录是内容工作区，运行在 `workspace-write` 沙箱中。
- `GET /api/inspirations` 读取最新 Markdown 简报并拆成结构化条目，不使用远程数据库。
- `POST /api/chat` 通过 SSE 返回 Codex 的进度、回复和文件变更。
- 用户创作内容与对话状态均被 Git 忽略，公共仓库只保存代码、模板和示例规则。

## 持久化分层

| 数据 | 保存位置 | 作用 |
|---|---|---|
| 稿件、选题、封面、发布数据 | `00_收件箱` 至 `04_复盘` | 内容的唯一事实来源，关闭页面和重启服务后仍可读取 |
| Codex 线程与最近 60 条对话 | `web/.workbench/state.json` | 继续本地对话；临时文件写完后再原子替换正式状态 |
| 极简/专业模式、内容类型、未发送草稿 | 浏览器本地存储 | 仅用于恢复当前设备的界面偏好和临时输入 |

项目是本地工作台，因此不引入云数据库。结构化内容继续使用透明、可备份、可迁移的本地文件；浏览器存储不作为正式内容来源。

## 灵感数据约定

最新简报必须包含 `## 5 条重点资讯`，每个条目使用 `### 1. 标题` 开始，并提供“发生了什么”“为什么重要”“AIHOT”和“原文”。解析器最多展示五条；缺少原文时标记为“待核验”。
