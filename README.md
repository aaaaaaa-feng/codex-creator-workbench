# Codex Creator Workbench

[![CI](https://github.com/xue-feng-bai/codex-creator-workbench/actions/workflows/ci.yml/badge.svg)](https://github.com/xue-feng-bai/codex-creator-workbench/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-2563eb.svg)](LICENSE)
[![Node.js](https://img.shields.io/badge/Node.js-%E2%89%A522.13-339933.svg)](https://nodejs.org/)

**把你自己的 Codex 变成一套本地 AI 自媒体生产线。**

Codex Creator Workbench 是一个面向 AI 内容创作者的本地 Web 工作台。它把热点采集、灵感筛选、事实核验、口播与图文创作、封面生成、归档和复盘串成一条固定流程，同时保留创作者对选题、观点、成稿和发布的最终决定权。

```text
热点 / 想法
    ↓
采集与去重
    ↓
勾选值得讲的内容
    ↓
核验事实与来源
    ↓
视频母稿 / 图文母稿
    ↓
小红书 · 抖音 · B站 · 公众号 · X
    ↓
封面与素材 → 人工发布 → 数据复盘
```

内容文件、账号规则和 Codex 会话都保存在使用者自己的电脑上。项目不会自动发布内容，也不会把你的本地资料上传到维护者的服务器。

> 当前版本：早期可用版。核心的本地工作台、Codex 对话、AIHOT 热点池、批量生成科普稿、稿件阅读与复制、封面 Skill 调用和本地归档已经可用；多平台一键内容包、版本回滚和内容日历仍在路线图中。

## 它解决什么问题

AI 创作真正耗时的往往不是“让 AI 写一段话”，而是每天重复这些动作：

- 到处找热点，却很难判断哪条适合自己的账号。
- 同一事件有很多重复报道，原始来源和二手观点混在一起。
- 写完口播后，还要重新整理标题、镜头、封面和平台文案。
- 同一主题发到不同平台时，只能复制粘贴，很快失去平台语感。
- 稿件散落在聊天记录里，发布后也没有可复用的复盘。

这个项目把重复劳动交给 Codex，把判断留给人：

| Codex 负责 | 创作者负责 |
|---|---|
| 搜索、去重、整理和格式转换 | 账号定位与最终选题 |
| 根据来源生成初稿与平台版本 | 个人经历、观点和审美 |
| 生成镜头、标题、封面提示和清单 | 确认事实、采用哪一版稿 |
| 把文件放入统一目录 | 拍摄、发布与对结果负责 |

## 当前已经可以做什么

### 1. 今日灵感池

- 让 Codex 实际调用已经配置的 AIHOT MCP，采集过去 24 小时资讯和当前热榜。
- 按同一事件去重，固定整理为 5 条候选热点。
- 每条热点只占一行；点击展开后查看摘要、编辑判断、AIHOT 链接和原始来源。
- 勾选其中一条或多条，打包交给 Codex 生成普通人能听懂的科普稿。
- 每次采集都保存为新的本地简报，不覆盖历史记录。

### 2. 稿件与 Codex 对话

- 在 Web 页面里像使用 Codex 对话框一样输入自然语言指令。
- Markdown 文件会渲染为非编辑状态的阅读版，不直接展示满屏 Markdown 符号。
- 一键复制去掉 Markdown 标记后的正文，适合粘贴到提词器或平台后台。
- 从稿件详情直接打开右侧 Codex 对话，让它缩短、重写、核验或补充镜头。
- Codex 可以继续使用当前项目的规则、本地文件、MCP 和已安装 Skill。

### 3. 封面生成与归档

- 从选题或稿件一键填写封面任务。
- 可调用 `$artifact-template-creator`，生成 3 张竖版和 3 张横版封面。
- 封面自动归档到对应主题的 `封面/` 目录。
- 封面生成前仍由创作者确认标题、人物和证据图，避免错误内容直接进入成品。

### 4. 本地内容流水线

- `00_收件箱`：AIHOT 日报、专题搜索、暂未筛选的信号。
- `01_待选题`：准备深挖或生成初稿的主题。
- `02_制作中`：已核验、正在拍摄或排版的内容。
- `03_已发布`：作品、平台链接和最终版本。
- `04_复盘`：72 小时数据、结论和下一次只改的一件事。

一个主题只保留一个主目录，随状态移动，不在多个阶段复制出互相冲突的版本。

## 3 分钟开始使用

### 使用前准备

你需要：

1. macOS、Windows 或 Linux。
2. [Node.js](https://nodejs.org/) 22.13 或更高版本。
3. 已经安装、登录并能正常使用的 Codex。

工作台使用你电脑上的 Codex 配置和身份，不要求把 OpenAI API Key 写进这个仓库。

### 方法一：下载后双击，适合非技术用户

1. 点击 GitHub 页面右上方的 **Code → Download ZIP**。
2. 解压 `codex-creator-workbench-main.zip`。
3. 启动：
   - macOS：双击 `启动自媒体工作台.command`。
   - Windows：双击 `start-workbench.bat`。
   - Linux：在项目目录运行 `npm start`。
4. 首次启动会自动准备依赖和本地文件，完成后自动打开 `http://localhost:3000/`。

首次准备完成后，后续通常只需再次双击启动文件。首次安装仍需要网络连接；Codex 或 Node.js 未安装时，启动器会给出明确提示。

> macOS 如果阻止首次打开，可在 Finder 中右键启动文件并选择“打开”。不要为了省事关闭系统安全保护。

### 方法二：Git 克隆，适合开发者

```bash
git clone https://github.com/xue-feng-bai/codex-creator-workbench.git
cd codex-creator-workbench
npm start
```

`npm start` 会依次：

1. 检查 Node.js 版本。
2. 安装 `web/` 所需依赖。
3. 从公开模板创建本地账号规则和内容目录。
4. 启动 Web 页面与本地 Codex 桥接。
5. 在浏览器中打开工作台。

## 它怎样连接到你的 Codex

页面不会把一套公共 AI 账号共享给所有人。后端通过官方 `@openai/codex-sdk` 在你的电脑上启动、继续和恢复 Codex 任务，因此沿用的是使用者自己的 Codex 环境、权限、项目规则、MCP 和 Skills。

```text
浏览器页面
  └─ http://localhost:3000
       └─ 本地桥接服务（仅监听 127.0.0.1）
            └─ Codex SDK
                 └─ 你的 Codex 身份 / MCP / Skills / 本地项目
```

官方 SDK 的能力与运行方式可查看 [OpenAI Codex SDK 文档](https://learn.chatgpt.com/docs/codex-sdk)。

安全边界：

- 桥接服务默认只监听 `127.0.0.1`，不会主动暴露到局域网或公网。
- 个人内容、`AGENTS.md`、`.env.local` 和本地状态默认不会进入 Git。
- 真正发布、评论、点赞、私信等外部动作不会被默认执行。
- 如果你主动配置第三方 MCP，传给该服务的数据受对应服务的规则约束，请自行检查其隐私条款。

## 可选：连接 AIHOT

没有 AIHOT 时，工作台仍可用于手工灵感、写稿、改稿、封面和归档；“采集今日热点”需要你自己的 AIHOT MCP。

```bash
codex mcp add aihot --url '<你的 AIHOT MCP 地址>'
```

配置后重新启动工作台。不要把包含个人标识或访问凭证的 MCP URL 写进 README、截图、`.env` 示例或 Git 提交。

## 第一次个性化

```bash
cp web/.env.example web/.env.local
```

你可以在 `.env.local` 中设置创作者名称、角标和封面 Skill 名称。首次运行还会从 `AGENTS.example.md` 创建只属于你的 `AGENTS.md`。

建议在 `AGENTS.md` 一次写清：

- 你主要为谁创作。
- 你擅长解释什么、回避什么。
- 默认语气、时长和视频节奏。
- 常用平台及其表达偏好。
- 哪些事实必须打开原文核验。
- 哪些外部动作必须先得到你确认。

以后你不必每次重复这些背景。

## 一条内容的标准流程

| 阶段 | 你要做的决定 | 工作台怎样帮你 |
|---|---|---|
| 定位 | 为谁讲，为什么值得听你讲 | 用 `AGENTS.md` 固化受众、语气和边界 |
| 采集 | 今天发生了什么 | AIHOT 最新资讯、热榜和专题搜索 |
| 筛选 | 哪条值得讲 | 去重、五维评分、单行热点池、展开和多选 |
| 核验 | 哪些是事实、报道、观点或推断 | 保留原始来源、核验状态和风险边界 |
| 设计 | 用口播、教程、测评还是图文 | 从共同事实底稿生成内容母稿 |
| 制作 | 还缺哪些镜头、录屏、图片和封面 | 生成分镜、素材清单、标题和封面任务 |
| 适配 | 同一主题怎样进入不同平台 | 在事实不变的前提下重组表达方式 |
| 发布 | 现在是否可以发 | 做发布前检查，真正发布由人确认 |
| 复盘 | 什么值得继续 | 记录真实数据，一次只确定一个主要变化 |

完整产品设计和功能优先级见 [AI 内容创作者工作流与产品路线图](docs/CREATOR_WORKFLOW.md)。

## 支持哪些内容类型

### 视频

| 类型 | 推荐内容包 |
|---|---|
| 热点口播 / 新闻解读 | 3 秒开场、20–45 秒母稿、镜头建议、来源、标题、评论问题 |
| 教程 / 录屏演示 | 结果先行、适用人群、前置条件、步骤、成功标志、常见失败、录屏清单 |
| 对比 / 测评 | 同一任务、同一输入、同一评分标准、实测证据、限制 |
| 体验 / Vlog | 使用场景、真实过程、意外发现、个人判断和可验证结果 |
| 深度视频 | 章节结构、证据卡、案例、反方观点、B-roll 与资料清单 |

教程类内容可直接从 [教程视频模板](90_模板/教程视频模板.md) 开始。

### 图文与平台适配

先保留一份共同的事实底稿，再按阅读场景分别创作：

| 平台 | 重点不是字数，而是阅读场景 |
|---|---|
| 小红书 | 真实体验、短段落、图片页结构、首图短句和可收藏信息 |
| 抖音 | 强结果开场、口语节奏、画面动作、简短文案和评论问题 |
| B站 | 完整解释、视频简介、章节、动态摘要、置顶评论和可复现材料 |
| 公众号 | 背景、导语、小标题、完整论证、来源和必要声明 |
| X / Twitter | 高密度单帖或线程，突出事实、判断、链接和讨论空间 |

平台规则会变化，因此项目固定的是创作逻辑，不会把某个时期的流量技巧写成永恒规则。可使用 [平台适配包模板](90_模板/平台适配包模板.md) 确保不同版本共享同一事实和来源。

## 常用指令

在右侧 Codex 对话框里，你可以直接说：

| 你的话 | 默认结果 |
|---|---|
| “今天有什么值得做？” | 采集过去 24 小时热点，去重后整理 5 条 |
| “把勾选的三条做成选题包” | 核验来源，并分别生成可拍的科普稿 |
| “把这条改成 30 秒，像在和朋友解释” | 基于当前稿件改写并保留事实边界 |
| “把它做成教程视频” | 生成结果、步骤、录屏、失败处理和素材清单 |
| “生成小红书、抖音、B站、公众号和 X 版本” | 共享事实底稿，分别适配表达 |
| “这句话有证据吗？” | 回到原始来源核对，不用语气掩盖不确定性 |
| “给这篇稿做封面” | 填写封面任务并调用配置的封面 Skill |
| “复盘这条，只告诉我下一条该改什么” | 根据真实数据找一个最值得验证的变化 |

## 项目结构

```text
codex-creator-workbench/
├── .github/                # CI、Issue 与 PR 模板
├── AGENTS.example.md       # 可公开的 Codex 项目规则模板
├── 00_收件箱/              # 本地热点简报和原始灵感
├── 01_待选题/              # 候选选题和初稿
├── 02_制作中/              # 已核验、正在制作的内容
├── 03_已发布/              # 最终作品与真实链接
├── 04_复盘/                # 数据与周期复盘
├── 90_模板/                # 口播、教程、平台适配、发布复盘模板
├── docs/                   # 架构与创作者工作流
├── scripts/                # 初始化和一键启动逻辑
├── web/                    # Web 页面、本地桥接、测试
├── start-workbench.command # macOS 英文启动器
├── 启动自媒体工作台.command # macOS 中文启动器
└── start-workbench.bat     # Windows 启动器
```

`00_收件箱` 到 `04_复盘` 中只提交了说明文件。你真正的选题、稿件、封面和数据会被 `.gitignore` 排除。

## 路线图

### P0：优先减少每天的重复劳动

- [ ] 内容类型选择器：口播、教程、对比、体验、图文、长文。
- [ ] 一键生成多平台内容包，并排预览差异。
- [ ] 稿件版本比较、接受修改和一键回滚。
- [ ] 教程视频生成器：步骤、录屏、报错和可复现材料一次完成。
- [ ] 内容日历：统一查看待选题、制作中、待发布和复盘。

### P1：提升内容质量与一致性

- [ ] 逐句事实证据卡和来源冲突提示。
- [ ] 分镜与素材看板、提词器稿和字幕导出。
- [ ] 系列化创作和重复选题提醒。
- [ ] 真实数据图表与不同内容系列对比。

### P2：可扩展的创作者生态

- [ ] 可插拔热点源、封面 Skill、字幕、剪辑和数据连接器。
- [ ] 平台草稿导出；任何真正发布仍保留人工确认。
- [ ] 多人审稿、批注和角色权限。
- [ ] 素材版权、AI 生成标记和平台风险检查。

欢迎在 [Issues](https://github.com/xue-feng-bai/codex-creator-workbench/issues) 提交需求。请描述你的实际创作流程和卡点，而不只是功能名称。

## 常见问题

<details>
<summary><strong>这是一个在线 SaaS 吗？</strong></summary>

不是。它是运行在你电脑上的本地 Web 应用。浏览器只是操作界面，内容和 Codex 执行仍在本地。
</details>

<details>
<summary><strong>别人下载后会连接到我的 Codex 吗？</strong></summary>

不会。每个人连接的是自己电脑上已经安装并登录的 Codex。仓库不包含维护者的账号、会话、MCP 地址或个人内容。
</details>

<details>
<summary><strong>一定要使用 AIHOT 吗？</strong></summary>

不一定。AIHOT 只负责实时热点入口；手工输入灵感、写稿、改稿、封面和归档不依赖 AIHOT。
</details>

<details>
<summary><strong>为什么不自动发布到各平台？</strong></summary>

发布会影响真实账号、受众和平台合规。项目当前把生成与整理自动化，把最终审稿和发布保留为明确的人类关口。
</details>

<details>
<summary><strong>能否做到真正的“什么都不安装，一次点击”？</strong></summary>

当前不能诚实地这样承诺。现阶段需要先具备 Node.js 和可用的 Codex；完成首次准备后可以双击启动。未来可以增加签名桌面安装包，但仍需要使用者登录自己的 Codex。
</details>

## 三条创作原则

1. **热点是入口，不是内容本身。** 观众真正关心的是“这和我有什么关系”。
2. **工具是证据，不是主角。** 真人经历和创作者自己的判断才形成长期价值。
3. **可以慢一点，但不能掺假。** 已核实、待核实、观点和预测始终分开。
