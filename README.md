# Codex Creator Workbench

一个本地优先、由 Codex 驱动的 AI 自媒体工作台：采集热点、勾选灵感、生成科普稿、制作封面并复盘内容。

> AIHOT 找热点 → 整理成 5 条 → 勾选值得讲的内容 → Codex 生成科普稿 → 封面 → 发布与复盘

内容和 Codex 会话都保存在使用者自己的电脑上。本项目不会自动发布内容，也不会把本地资料上传到项目维护者的服务器。

## 快速开始

### 环境要求

- macOS、Windows 或 Linux。
- Node.js 22.13 或更高版本。
- 已安装并登录 Codex。工作台使用本机 Codex 身份，不要求把 OpenAI API Key 写进项目。

### 启动

```bash
git clone <你的仓库地址>
cd codex-creator-workbench
npm start
```

首次启动会自动安装 `web/` 所需依赖并创建本地内容文件。macOS 也可以双击 `start-workbench.command`，Windows 可以双击 `start-workbench.bat`。

工作台默认在 `http://localhost:3000/` 打开，Codex 桥接只监听 `127.0.0.1`。

### 连接 AIHOT

热点采集是可选集成。请使用你自己的 AIHOT MCP 地址：

```bash
codex mcp add aihot --url '<你的 AIHOT MCP 地址>'
```

不要把带个人标识的 MCP 地址提交到 Git。配置后重新启动工作台，右上角 AIHOT 状态会变为可用。

### 个性化

```bash
cp web/.env.example web/.env.local
```

在 `.env.local` 中填写创作者名称、角标和可选封面 Skill 名称。首次运行还会从 `AGENTS.example.md` 创建本地 `AGENTS.md`，你可以在里面修改受众、平台、语气和事实核验规则。

## Web 工作台

本项目配有本地 Web 操作页面。macOS 双击根目录的 `启动自媒体工作台.command`，页面会自动在 Google Chrome 打开。

工作台可以：

- 展示 `00_收件箱` 到 `04_复盘` 的本地内容。
- 像 Codex 对话框一样直接输入自然语言指令。
- 通过官方 Codex SDK 继续使用 AIHOT MCP、项目规则和本地文件能力。
- 把一份简报拆成 1–5 条独立热点，支持展开、多选和批量生成科普稿。
- 调用 `$artifact-template-creator` 生成三张竖版和三张横版封面，归档到主题的 `封面/` 目录。

页面本身位于 `web/`，内容仍保存在当前项目根目录，不会锁进某个网页数据库。

使用者只需在本地 `AGENTS.md` 写一次账号定位，后续任务会自动继承，不必重复说明。

## 你以后只需要这样说

| 你的话 | 我默认会做什么 | 文件放在哪里 |
|---|---|---|
| “今天有什么值得做？” | 查 AIHOT 过去 24 小时和当前热榜，去重后整理为 5 条 | `00_收件箱/` |
| “查一下 OpenAI 最近有什么” | 查近 7 天相关资讯，补充原始来源并形成专题简报 | `00_收件箱/` |
| “把第 2 条做成口播” | 建立选题卡和一版可直接拍的口播稿 | `01_待选题/` |
| “再深挖一下” | 补查原文、反方材料、争议点和普通人影响 | 当前选题目录 |
| “我准备拍了” | 做事实、措辞和时长检查，生成拍摄清单 | `02_制作中/` |
| “我发了，小红书链接是……” | 归档作品并登记真实数据 | `03_已发布/`、`04_复盘/` |
| “复盘这条” | 根据真实数据判断保留什么、下一条只改什么 | `04_复盘/` |
| “做本周复盘” | 汇总一周结果，给下周最多 5 个变体 | `04_复盘/` |

最常用的一条指令就是：

> 今天有什么值得做？

## 文件夹怎么流转

```text
codex-creator-workbench/
├── AGENTS.md            # Codex 每次自动遵守的项目规则
├── README.md            # 你现在看的使用说明
├── 选题看板.md           # 当前内容状态的入口
├── 00_收件箱/            # AIHOT 日报、专题搜索、暂未筛选的信息
├── 01_待选题/            # 已决定考虑，但还没最终定稿
├── 02_制作中/            # 已核验，正在拍摄或剪辑
├── 03_已发布/            # 成片记录和发布链接
├── 04_复盘/              # 72 小时数据与周期复盘
└── 90_模板/              # 简报、选题、口播和复盘模板
```

一个主题只保留一个主目录，随着状态变化移动，不在多个阶段复制出互相冲突的版本。

## 固定生产流程

### 1. 发现：每天只收集，不急着全做

AIHOT 用法默认如下：

- 过去 24 小时的新消息：`aihot_get_latest`
- 此刻热榜：`aihot_get_hot_topics`
- 指定公司、模型、产品或人物：`aihot_search`
- 某个热榜事件的时间线：先从热榜取得公开 ID，再用 `aihot_get_story`

日报会保留 AIHOT 链接，并把重复报道合并成同一事件。

### 2. 筛选：新闻重要，不等于适合你的账号

每个候选从五方面各评 1–5 分：

- 热点强度
- 普通人相关
- 反差与观点
- 可视化
- 可延展

每天最多推荐 3 个角度，只重点建议其中 1 个。没有合适选题时会明确说“今天不建议硬追”，不为了日更凑稿。

### 3. 核验：先把事实和观点分开

进入口播前至少完成：

- 打开原始链接确认标题、日期和关键数字。
- 标出信息属于官方确认、媒体报道还是个人推断。
- 找不到原文时写“未完成原文核验”，不换一种肯定语气蒙混过去。
- 口播稿保留来源，但不会把引用链接念进视频。

### 4. 制作：默认交付一套能直接拍的内容包

你选中一条后，我默认交付：

1. 一张选题卡。
2. 三个 3 秒开场，推荐其中一个。
3. 一版 20–45 秒口播稿。
4. 真人画面、录屏或新闻截图的镜头清单。
5. 三个标题、两个封面短句和一段发布文案。
6. AIHOT 链接、原始来源和需要谨慎表达的地方。

默认结构是：

> 结果或反差 → 发生了什么 → 和普通人有什么关系 → 创作者的判断 → 留一个自然问题

### 5. 发布与复盘：72 小时后再判断

发布时只记录真实数据。没有的数据保留“待填写”，不估算。

判断方向时优先看：

1. 收藏和收藏率。
2. 有内容的评论，而不是表情或互赞。
3. 评论中是否出现“想看后续”“这个和我有关”等关注意愿。
4. 完播表现。
5. 播放、点赞和新增关注。

一次复盘只确定一个主要变化，例如只改开场、只改选题角度或只改时长，避免同时改五件事后无法判断原因。

## 现在没有清晰方向，前 9 条怎么试

先做小样本验证，不要求连续日更：

| 类型 | 数量 | 主要问题 | 示例角度 |
|---|---:|---|---|
| 强共鸣 | 3 | AI 变化和普通人的焦虑、机会有什么关系 | “这次变化真正影响的不是程序员” |
| 真实反差 | 3 | 新闻标题和真实情况有什么落差 | “大家都在聊模型，巨头抢的却是电” |
| 新鲜体验 | 3 | 创作者亲自试过之后发现什么 | “我把这个新功能真的用了一遍” |

建议每周约 3 条、相隔一天发布，单条观察约 72 小时。9 条完成后，不按最高播放量直接定方向，而是综合收藏、有效评论和关注意愿，选出一个方向再做 5 个不同故事的变体。

## 三条长期原则

1. **热点是入口，不是内容本身。** 观众真正关心的是“这和我有什么关系”。
2. **工具是证据，不是主角。** 真人体验和创作者自己的判断才形成个人 IP。
3. **可以慢一点，但不能掺假。** 已核实、待核实、观点和预测始终分开。
